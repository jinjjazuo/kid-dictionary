# Kids Dictionary — Design Spec
**Date:** 2026-04-09

## Overview

A web app that helps kids aged 4–10 learn new words through on-demand illustrated comic storybooks with narration, and reinforce them through a personal dictionary and mini games.

The core insight: kids can't look up words they don't understand because dictionary definitions use words they also don't know. This app bridges that gap with visual, narrative-driven word explanations.

---

## Target Users

| Group | Age | Experience |
|---|---|---|
| Young readers | 4–6 | Pre/early readers, audio-first, simple words |
| Older readers | 7–10 | Can read independently, school vocabulary |

Age group is selected at signup. Ages 4–6 map to the young group; ages 7–10 map to the older group. Age group affects story length, vocabulary complexity, and UI scale.

**Guest users** (not signed in) default to the young group (4–6) for all word lookups.

---

## Authentication Boundaries

- **Unauthenticated users:** can search a word and view the full comic storybook experience
- **Authenticated users only:** can save words to their dictionary, view `/dictionary`, and play games
- If an unauthenticated user clicks "Add to My Dictionary", they are prompted to sign up first

---

## Core User Flow

1. Kid searches a word
2. App checks global word cache keyed by `(word, age_group)` in Supabase DB
   - **Cache hit:** return stored script + comic image for that age group
   - **Cache miss:** generate story script via Claude API → generate comic strip image via Flux → cache both
3. Word page displays: definition, comic strip, scene-by-scene narration (Web Speech API)
4. Kid clicks "Add to My Dictionary" (requires auth)
5. Later: kid visits /games to play Quiz or Crossword using their saved words

## Word Page — Dictionary Section

The word page functions as a full kids' dictionary entry before the comic storybook plays. All dictionary data is sourced from `api.dictionaryapi.dev` and then enriched/simplified by Claude per age group. This enrichment is cached alongside the comic data in the `words` table.

**Word page sections (in order):**
1. **Word** — displayed large in Fredoka One
2. **Pronunciation** — phonetic spelling (e.g. `/ɪˈnɔːməs/`) + audio button (audio URL from dictionary API, played via `<audio>` element)
3. **Simplified definition** — Claude rewrites the raw definition into plain language a child can understand, tailored to age group
4. **Example sentences** — 2 age-appropriate example sentences generated by Claude (not from dictionary API, which can be complex)
5. **Synonyms** — up to 4 synonyms from the dictionary API, each is a tappable link to search that word
6. **Comic storybook** — plays below the dictionary section

**Data sourcing:**
- Raw definition, phonetic text, pronunciation audio URL, and synonyms → `api.dictionaryapi.dev`
- Simplified definition + example sentences → Claude API (cached, not regenerated on each visit)

**Claude prompt for dictionary enrichment:**
- Age 4–6: `"Simplify this definition for a 5-year-old in one short sentence: '[raw definition]'. Then write 2 example sentences using the word '[word]' that a 5-year-old would understand. Output JSON: {\"definition\": \"...\", \"examples\": [\"...\", \"...\"]}"`
- Age 7–10: `"Rewrite this definition clearly for a 9-year-old: '[raw definition]'. Then write 2 example sentences. Output JSON: {\"definition\": \"...\", \"examples\": [\"...\", \"...\"]}"`

## The Comic Storybook (Core Feature)

Each word + age group gets one AI-generated comic strip image + a narrated script. Comics are cached per `(word, age_group)` so a 3-panel version exists for young readers and a 5-panel version for older readers, stored separately.

**Panel counts by age group:**
- Age 4–6: 3 panels
- Age 7–10: 5 panels

**Generation pipeline (runs once per word+age_group, cached forever):**
1. Claude API generates a scene-by-scene story script (3 or 5 scenes) tailored to the age group
2. The scenes are compiled into a single image prompt
3. Flux (via Replicate) generates one multi-panel comic strip image
4. Script + image URL saved to `words` table (unique on `word + age_group`)
5. Image file stored in Supabase Storage

**Playback experience:**
- Comic strip image is displayed in full
- A CSS highlight overlay (semi-transparent coloured border box) is positioned over each panel region as narration plays. Panels are equal-width columns (3 or 5) within the image container, calculated via CSS grid offsets — no image slicing needed.
- Narration plays scene by scene via Web Speech API (browser built-in, free)
- The target word is **bold/highlighted** in the scene text each time it appears

**Claude prompt strategy:**
- Age 4–6: `"Write a 3-scene story for a 5-year-old using the word [X]. Use simple words. Make it fun and silly. Output as a JSON array: [{\"scene\": 1, \"text\": \"...\"}]"`
- Age 7–10: `"Write a 5-scene story for a 9-year-old using the word [X]. Include context that makes the meaning clear. Output as a JSON array: [{\"scene\": 1, \"text\": \"...\"}]"`

**Flux image prompt template:**
The image prompt must specify equal-width panel layout explicitly to ensure reliable CSS overlay positioning:
`"A comic strip with exactly [N] equal-width vertical panels side by side, no borders between panels, flat illustration style, bright colours, child-friendly. Panel 1: [scene 1 text]. Panel 2: [scene 2 text]..."`
Panel highlight CSS overlay uses equal-width columns (100%/N per panel). Positioning is approximate — minor misalignment is acceptable.

**Error handling:**
- **Word validation:** Before calling any AI API, validate the word using `api.dictionaryapi.dev/api/v2/entries/en/[word]`. If the API returns 404, show "Hmm, we don't know that word!" and stop. This also prevents gibberish from reaching paid APIs.
- **Claude failure:** If Claude returns invalid JSON or fails after one retry, do NOT cache the row. Show the definition (from the dictionary API) as plain text with no comic.
- **Flux failure:** If image generation fails, cache the row in `words` with `comic_image_url: null`. Show the narrated script as text-only. The row is cached so future lookups skip image generation. Words cached in a degraded state (null image) are accepted MVP debt — there is no automatic retry mechanism at this stage.
- **Rate limiting:** All `/api/word/[word]` requests are rate-limited at the Vercel Edge layer (max 20 requests/minute per IP). Word input is capped at 50 characters. The dictionary API validation acts as a further filter against abuse.

## API Routes

### `GET /api/word/[word]?ageGroup=4-6|7-10`
Returns word data for the given word and age group. Unauthenticated requests default to `ageGroup=4-6`.
- **200:** `{ id: string, word: string, definition: string, examples: string[], synonyms: string[], phonetic: string | null, pronunciationUrl: string | null, storyScript: Scene[], comicImageUrl: string | null }`
- **404:** word not recognised (dictionary API returned 404)
- **500:** generation failed with no fallback available

### `POST /api/word/save`
Saves a word to the authenticated user's dictionary.
- Body: `{ wordId: string }` — `wordId` is the `id` returned by `GET /api/word/[word]`
- **200:** `{ success: true }`
- **401:** not authenticated
- **409:** word already in dictionary

### `GET /api/dictionary`
Returns the authenticated user's saved words.
- **200:** `{ words: UserWord[] }` — see Types section
- **401:** not authenticated

### `GET /api/games/quiz?count=10`
Returns MCQ questions generated from the user's saved words.
- **200:** `{ questions: QuizQuestion[] }` — see Types section
- **400:** fewer than 4 saved words
- **401:** not authenticated

### `GET /api/games/crossword`
Returns saved words with definitions for crossword generation (done client-side using `crossword-layout-generator`).
- **200:** `{ words: { word: string, definition: string }[] }`
- **400:** fewer than 4 saved words
- **401:** not authenticated

## Games

### Quiz (MCQ)
- Requires minimum 4 saved words to play
- Each question randomly picks one of two modes:
  1. Show a definition → pick the correct word (4 choices)
  2. Show a word → pick the correct meaning (4 choices)
- Wrong answer choices (distractors) are drawn from the user's other saved words (excluding the correct answer). If the user has 4 or fewer total saved words (meaning 3 or fewer other words available as distractors), the shortfall is supplemented with random entries from the global `words` table (same age group).
- Animated feedback: green celebration for correct, gentle red shake for wrong
- Score + encouragement shown at end of round
- Quiz results are not persisted (no history UI at this stage)

### Crossword
- Auto-generated using the `crossword-layout-generator` npm package
- Clues are the word definitions
- Minimum 4 saved words required
- If fewer than 4 words, show a friendly prompt encouraging the kid to save more words first

## Types

```ts
type AgeGroup = '4-6' | '7-10'

type Scene = {
  scene: number   // 1-indexed panel number
  text: string    // narration text for that panel
}

type UserWord = {
  id: string                   // user_words.id
  wordId: string               // words.id
  word: string
  definition: string
  examples: string[]
  synonyms: string[]
  phonetic: string | null
  pronunciationUrl: string | null
  comicImageUrl: string | null
  addedAt: string              // ISO timestamp
}

type QuizQuestion = {
  mode: 'word-to-meaning' | 'meaning-to-word'
  prompt: string       // the word or definition shown to the user
  choices: string[]    // 4 options (word strings or definition strings)
  answerIndex: number  // index of the correct choice in choices[]
}
```

## Data Model

```sql
-- Authentication is managed entirely by Supabase Auth (auth.users)
-- No custom password storage

profiles  -- extends Supabase auth.users
  id           uuid  references auth.users(id) primary key
  age_group    text  check (age_group in ('4-6', '7-10'))
  created_at   timestamptz default now()

words  -- global cache, keyed by (word, age_group)
  id                  uuid primary key default gen_random_uuid()
  word                text not null,
  age_group           text not null check (age_group in ('4-6', '7-10')),
  definition          text not null,          -- Claude-simplified, kid-friendly
  examples            jsonb not null,          -- array of 2 example sentences from Claude
  synonyms            jsonb not null,          -- array of up to 4 synonyms from dictionary API
  phonetic            text,                    -- e.g. "/ɪˈnɔːməs/" from dictionary API
  pronunciation_url   text,                    -- audio URL from dictionary API (nullable)
  story_script        jsonb not null,
  comic_image_url     text,                    -- nullable: null if image generation failed
  created_at          timestamptz default now()
  unique (word, age_group)

user_words  -- personal dictionary
  id         uuid primary key default gen_random_uuid()
  user_id    uuid references profiles(id)
  word_id    uuid references words(id)
  added_at   timestamptz default now()
  unique (user_id, word_id)
```

`story_script` JSONB structure:
```json
[
  { "scene": 1, "text": "Tim looks curious in his garden." },
  { "scene": 2, "text": "\"Wow!\" said Tim. \"That elephant is enormous!\"" }
]
```

## Tech Stack

| Layer | Tool | Notes |
|---|---|---|
| Frontend + Backend | Next.js (App Router) | API routes serve as backend |
| Auth + Database | Supabase | Postgres + Auth + Storage |
| Image Storage | Supabase Storage | Comic strip images cached here |
| Story generation | Claude API (Haiku) | ~$0.001/word |
| Image generation | Flux via Replicate | ~$0.003/image, one per word+age_group |
| Narration | Web Speech API | Browser built-in, free |
| Styling | Tailwind CSS | Utility-first CSS |
| Animations | Framer Motion | Panel highlights, game feedback |
| Fonts | Fredoka One + Nunito | Kid-friendly rounded fonts |
| Crossword | crossword-layout-generator | npm package |
| Deployment | Vercel | Free tier |

**Estimated cost per new word (per age group):** ~$0.004 (cached forever after first lookup)

## UI Design Principles

- **Kid-friendly palette:** bright yellows, oranges, greens; playful gradients
- **Large tap targets:** minimum 48px, good for small fingers on tablets
- **Bold rounded fonts:** Fredoka One for headings, Nunito for body text
- **Responsive:** mobile-first, optimised for tablets and desktop
- **Animations:** subtle bounces and pops on interactions; confetti on quiz completion
